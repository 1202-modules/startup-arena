# Этап 10 — сквозная приёмка и выпуск

## Паспорт этапа

- Статус: проверен с явно указанным ограничением браузерной эмуляции `prefers-reduced-motion`.
- Дата начала: 2026-09-30; фактическое закрытие: 2026-10-01.
- Зависимости: этапы 00–09; требования `DECISIONS.md`, `PRODUCT_SPEC.md`, `GAME_RULES.md`, `IMPLEMENTATION_PLAN.md` §§14–16.
- Цель: подтвердить полный цикл игры, три скрытых рынка, несколько игроков, RU/EN, сохранение, защиту закрытия и визуальную пригодность.
- Среда: локальный Chromium через CUA, обычная ширина встроенного браузера и явно установленная ширина 390×844; отдельные синтетические SQLite-файлы в `/tmp`. Production API проверен локальным HTTP smoke, приложение в браузере — через Vite dev.
- Данные проверки: только синтетические имена; пароль и содержимое тестовых БД в отчёт не записываются. Снимки находятся в журнале CUA задачи.

## Элемент 10.1 — автоматические проверки

- Статус: проверен.
- Цель и критерий: сборка общих контрактов, сервера и клиента; целочисленные деньги, миграции, API-переходы, приватность сценария, рейтинг и финализация.
- Фактические файлы: `shared/src/index.ts`, `shared/test/contracts.test.js`, `server/src`, `server/test`, `client/src`.
- Фактическое поведение: `npm run typecheck && npm test` завершились кодом 0 после последних изменений. Production build Vite собрал 47 модулей; все 6 test-файлов Node прошли.
- Проверки элемента: добавлены случаи 0/1/2/3 мест, ничьи и reduced-motion ветки для наград; добавлен серверный тест отказа всех session write-операций после `FINALIZED` при сохранении чтения.
- Отклонения и ограничения: API-проверка отсутствия секретов и будущих событий выполнена серверными тестами; на клиенте официальный денежный итог не рассчитывается.

## Элемент 10.2 — все рынки через браузер

- Статус: проверен.
- Цель и критерий: отдельный полный браузерный проход трёх раундов для Scenario 01, 02 и 03, с проверкой скрытия будущих событий до подтверждения.
- Фактические файлы: `server/src/scenarios`, `server/src/sessions`, `client/src/App.tsx`, `client/src/api.ts`.
- Фактический браузерный маршрут: на каждой отдельной временной БД один игрок прошёл решение → подтверждение → результат три раза → финал. До каждого решения найдено 0 DOM-элементов с будущими исходами; после подтверждения — 4 результата стартапов.
- Числа контрольных стратегий: Scenario 01 (GreenBox) `1000 → 1050 → 1123.50 → 1247.09 $`; Scenario 02 (VoltX) `1000 → 950 → 1130.50 → 599.17 $`; Scenario 03 (NovaMind) `1000 → 1130 → 1333.40 → 1426.74 $`.
- Визуальная проверка: карточки сигналов, результатов и финал игрока просмотрены встроенным зрением; отрицательный итог Scenario 02 после исправления окрашен как убыток.
- Отклонения и ограничения: сценарий в тестовой БД закреплялся подготовительным fixture только для приёмки; приложение не предоставляет игроку выбора сценария.

## Элемент 10.3 — последовательные участники

- Статус: проверен.
- Цель и критерий: не менее 10 завершённых сессий в одном event без очистки, у каждого старт ровно 100000 центов, рынок общий, рейтинг устойчив.
- Фактические файлы: `server/src/events/event-store.ts`, `server/src/sessions/session-store.ts`, `client/src/App.tsx`.
- Фактическая проверка: в одном событии Scenario 01 через настоящий браузер последовательно завершены 10 полных игр по три раунда. Каждый новый старт показывал 1000 $, итоговый рейтинг содержал 10 записей и места 1–10 в порядке серверных капиталов.
- Дополнительный путь: другое событие проверено с тремя последовательными участниками и разными стратегиями; лидеры менялись без изменения сценария.
- Ограничения: имена в журнале и БД проверки синтетические; список стратегий не публикуется как часть общего рейтинга.

## Элемент 10.4 — негативные пути и восстановление

- Статус: проверен.
- Цель и критерий: неверные суммы/состояния, повторные запросы, reload, ошибка пароля, запрет после закрытия, восстановление сети.
- Фактические файлы: `client/src/App.tsx`, `client/src/session-recovery.ts`, `server/src/app.ts`, `server/src/sessions/session-store.ts`, `server/src/events/event-store.ts`, серверные тесты.
- Браузер: ручные `2000` и `−1` для портфеля дали понятную ошибку/недоступное подтверждение; точная сумма с центами сохранилась после reload; результат раундов 1/2 и финал восстановились из БД. При временной остановке dev API экран показал ошибку соединения; после перезапуска результат второго раунда восстановился без потери капитала.
- Организатор: `Отмена` и Escape оставили event открытым; неверный пароль показал ошибку в окне; правильный пароль закрыл event. После reload закрытый рейтинг остался, новая игра не предлагается.
- Автоматически: повторные confirm/complete не создают вторую прибыль/результат, активный игрок запрещает закрытие, все session write-операции после закрытия отклоняются; чтение прежнего результата доступно.
- Дефекты: устаревший dev-процесс с прежней формой DTO дал ошибку восстановления; перезапуск с актуальной сборкой и повторный browser reload устранили её.

## Элемент 10.5 — полная локализация

- Статус: проверен.
- Цель и критерий: все экраны и события в RU/EN, неизменные бренды, сохранение выбора языка после reload.
- Фактические файлы: `client/src/i18n.ts`, `client/src/App.tsx`, `client/src/format.ts`, `server/src/scenarios`.
- Фактическая проверка: в браузере просмотрены RU и EN на старте, решении, результате, финале игрока, пароле, награждении и закрытом рейтинге. После перехода на `i18next`/`react-i18next` RU/EN повторно переключены на результате; reload сохранил EN. События и сигналы Scenario 01–03 были показаны на выбранном языке, бренды остались латинскими.
- Исправления: callback `t` стабилизирован через `useCallback`, поскольку первая версия после смены библиотеки вызывала повторный цикл загрузки; повторный reload прошёл. Добавлены plural-формы счётчика: браузер показал `1 player` и `1 участник`. Смена языка больше не запускает начальную загрузку сессии: ввод `12.34` сохранился после немедленного переключения RU→EN и последующего reload.
- Ограничения: переводы встроены в bundle; runtime-запросов к внешним сервисам нет.

## Элемент 10.6 — визуальная приёмка

- Статус: проверен для обычного режима; отдельная браузерная эмуляция reduced motion недоступна в текущем CUA.
- Цель и критерий: осмотр реальных изображений старта, решения, деталей, результата, финала игрока, пароля, наград и рейтинга; отсутствие обрезки и переполнения на узкой ширине.
- Фактические файлы: `client/src/styles.css`, `client/src/App.tsx`.
- Фактическая проверка: встроенным зрением просмотрены desktop и 390×844 кадры старта, карточек, раскрытых деталей, сводки, результата, финала, пароля, серебряной общей карточки и закрытого рейтинга. В браузере при 390 px `document.documentElement.scrollWidth` не превышал `window.innerWidth`. Кнопка пропуска церемонии сработала от Enter и сразу открыла полный рейтинг.
- Исправления и повторный осмотр: мобильная сводка перемещена после карточек; результат после исправления осмотрен с правильным порядком. Убыточный итог окрашен красным и повторно осмотрен. Карточка награды теперь перемонтируется при смене места (`key={place}`); место 2 осмотрено после исправления, 3→2→1 наблюдались в браузере.
- Ограничение: у CUA есть управление viewport, но нет media-эмуляции `prefers-reduced-motion`; ветка `skipAwardAnimation` и CSS media проверены кодом/автотестом, визуальный кадр этого системного режима не получен. Снимки во время 560 ms reveal могут попадать в промежуточную полупрозрачную фазу, поэтому оценка читабельности сделана по кадрам после неё.
