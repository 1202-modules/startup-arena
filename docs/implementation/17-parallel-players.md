# Этап 17 — Параллельные игроки

## Паспорт этапа

- Статус: проверен. Начало и завершение: 2026-10-02.
- Зависимости: этап 16 проверен; серверная БД до обновления имела схему v3.
- Требования: DECISIONS.md «Изменение 2026-10-02 — параллельные игроки», PRODUCT_SPEC.md §1, §7, §9, GAME_RULES.md §8.
- Цель: снять ограничение одной активной сессии на event, сохранив независимость игроков, общий рынок, рейтинг и рабочие сохранения.
- За пределами этапа: комнаты, синхронизация действий и отдельный мобильный дизайн.

## 17.1 — Миграция и создание сессий

- Статус: проверен.
- Контракт до реализации: `POST /api/sessions` создаёт независимую сессию с 100000 центами при наличии других активных сессий. Повтор нормализованного имени в event даёт 409. Миграция v3→v4 удаляет только индекс одной активной сессии; ранее сохранённые данные не меняются. Свежая БД проходит ту же миграцию.
- Критерии приёмки: две активные сессии создаются в одном event; индекс снят; оба ID читаются после повторного открытия БД; дубль имени отклоняется.
- Фактические файлы: `server/src/db/migrations.ts`, `server/src/sessions/session-store.ts`, `server/test/database.test.js`, `server/test/legacy-migration.test.js`, `server/test/sessions.test.js`.
- Факт: миграция v3→v4 атомарно снимает частичный уникальный индекс, оставляя данные и уникальность нормализованного имени. `createSession` больше не отвергает второго активного участника. Новая и сохранённая БД проходят миграцию.
- Автоматическая проверка: тесты двух активных сессий, независимого капитала, миграции файловой v3 и legacy v2, повторного имени прошли. Два целевых теста сначала упали на старом правиле и версии схемы, затем прошли. Общий `npm test`: 3 shared + 42 server, 0 ошибок.
- Браузерная/визуальная проверка: интеграция проверена в 17.3; отдельного интерфейса у элемента нет.
- Отклонения и ограничения: отсутствуют. Итог: проверен.

## 17.2 — Изоляция и закрытие

- Статус: проверен.
- Контракт до реализации: подтверждение раунда одного игрока не меняет капитал, портфель и статус другого; оба видят один сценарий. Закрытие с любой активной сессией запрещено; после завершения или отмены всех сессий возможно.
- Критерии приёмки: отдельные состояния и стартовые суммы, общий event; `SESSION_ALREADY_ACTIVE` на закрытии до завершения обоих; успешное закрытие после завершения обоих.
- Фактические файлы: `server/src/events/event-store.ts`, `server/test/finalization.test.js`, `server/test/sessions.test.js`, `client/src/i18n.ts`.
- Факт: каждый участник сохраняет независимые ID, капитал и результаты; рынок остаётся общим. Закрытие ждёт всех активных участников. RU/EN сообщение теперь говорит обо всех активных играх.
- Автоматическая проверка: тест закрытия при двух активных игроках блокирует попытку до завершения каждого, после второго закрывает event; весь `npm test` прошёл. Предыдущие тесты отсутствия утечки будущих данных также прошли.
- Браузерная/визуальная проверка: отдельный тестовый event на локальном сервере; правильный тестовый пароль при активной игре показал блокировку на RU и EN; снимок окна RU просмотрен встроенным зрением. После отмены игры закрытие через браузер прошло. Первое прохождение выявило устаревший текст про одного участника; текст исправлен и повторно проверен.
- Отклонения и ограничения: отсутствуют. Итог: проверен.

## 17.3 — Браузер и развёртывание

- Статус: проверен.
- Контракт до реализации: независимые браузерные профили запускают игры одновременно, проходят три раунда и попадают в общий рейтинг. Браузер показывает корректные ошибки и восстановление после перезагрузки. Деплой сохраняет серверный том SQLite.
- Критерии приёмки: локальная сборка, typecheck, все тесты; параллельный браузерный путь с просмотром снимков; резервная копия рабочей БД до деплоя; новая версия здорова и принимает параллельные игры без тестовых записей в рабочей БД.
- Фактические файлы: `AGENTS.md`, `DECISIONS.md`, `PRODUCT_SPEC.md`, `GAME_RULES.md`, `IMPLEMENTATION_PLAN.md`, `ARCHITECTURE.md`, `DATA_MODEL.md`, `README.md`, `TESTING.md`, этот отчёт.
- Локальная среда: Node 22.23.2, временные SQLite и два браузера (Codex In-app Browser RU, Chrome EN). Node 20 при начальном запуске нативного `better-sqlite3` дал SIGSEGV; после выбора проектного Node 22 тесты исполняются штатно.
- Автоматическая проверка: `npm test` — production build, 3 shared + 42 server теста, 0 ошибок; `npm run typecheck` и `git diff --check` — без ошибок.
- Браузерная проверка: оба браузера одновременно начали игру с 1000 $, один оставил cash, второй вложил всё в NovaMind; после перезагрузки каждый восстановил собственный раунд. Оба прошли три раунда, получили разные результаты и общий рейтинг 2 участников. Третья тестовая игра заблокировала закрытие (`409 SESSION_ALREADY_ACTIVE`) и была отменена без записи в рейтинг; затем event завершился. RU/EN окно блокировки и восстановление проверены отдельно.
- Визуальная проверка: встроенным зрением просмотрены снимки двух параллельных экранов решения, персональных итогов, окна ошибки, награждения и полного рейтинга. Снимки в журнале браузерной проверки этой задачи; реальные имена и рабочая БД не использовались.
- Деплой: до обновления при 0 активных игроках создана отдельная резервная копия рабочей SQLite; `integrity_check=ok`. В Docker собран и запущен новый `platypus-game:latest`, финальный image ID `sha256:c0d5d6c916cfd8e796939e0bac38477c9ebe4f349f907003fc340903c9108899`. Контейнер healthy; HTTP health и HTTPS proxy ответили 200; рабочая БД `user_version=4`, `integrity_check=ok`, индекс лимита отсутствует, количество сохранённых участников осталось 7. Финальный образ на отдельной копии резервной БД успешно создал две активные сессии; тестовые участники в рабочую БД не записывались.
- Ограничения: отдельная мобильная версия не создавалась по требованиям. Итог: проверен.
