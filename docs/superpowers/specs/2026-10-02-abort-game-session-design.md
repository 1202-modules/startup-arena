# Дизайн функциональности отмены/выхода из игры во время матча (Abort Session)

**Дата:** 2026-10-02
**Область:** Сервер (API, SQLite) и Клиент (React 19, UI/UX, i18n)
**Режим работы:** Строго локальная разработка и тестирование (деплой на удаленный сервер запрещен до проверки пользователем).

---

## 1. Назначение и цели

Предоставить игроку или ведущему возможность прервать текущий активный матч в любой момент (раунды 1, 2, 3), вернувшись на стартовый экран регистрации с 1000 $ капитала.
- Сессия считается неудачной/отмененной.
- Данные прерванной игры не заносятся в общий лидерборд.
- Имя участника освобождается, позволяя при необходимости ввести его повторно.
- Активная сессия удаляется из базы данных, освобождая слот для следующего игрока (снимается блокировка `SESSION_ALREADY_ACTIVE`).
- Защита от случайного нажатия: диалог подтверждения перед отменой.

---

## 2. Архитектура и контракты

### 2.1. Backend API (`@startup-game/server`)
- **Эндпоинт:** `DELETE /api/sessions/:id`
- **Логика выполнения:**
  1. Валидация формата UUID `id`.
  2. Проверка существования сессии: если не найдена — `404 SESSION_NOT_FOUND`.
  3. Проверка статуса: сессия должна принадлежать текущему мероприятию. Если статус уже `COMPLETED` — `409 INVALID_STATE` (завершенные игры из лидерборда удалять через этот эндпоинт нельзя).
  4. В атомарной транзакции SQLite (`database.transaction`):
     - `DELETE FROM round_results WHERE participant_id = ?`
     - `DELETE FROM portfolios WHERE participant_id = ?`
     - `DELETE FROM participants WHERE id = ?`
  5. Возврат статуса `HTTP 204 No Content` (или `HTTP 200 { status: "ok" }`).

### 2.2. Frontend API Client (`client/src/api.ts`)
- Добавление метода:
  ```typescript
  abortSession(id: string): Promise<void>
  ```
  Выполняет `DELETE /api/sessions/${id}` с обработкой сетевых ошибок.

### 2.3. Frontend UI/UX (`client/src/App.tsx`, `client/src/i18n.ts`, `client/src/styles.css`)
- **Кнопка в топбаре:**
  - Отображается только тогда, когда активна сессия (`session && session.status !== "COMPLETED"`).
  - Стилизована как деликатная кнопка с текстом и иконкой: `Прервать игру` (RU) / `Quit game` (EN).
- **Диалог подтверждения (Confirm Dialog):**
  - Нативный `<dialog>` с фокусом и поддержкой клавиши Escape.
  - Текст:
    - Заголовок: «Прервать игру?» / «Quit the game?»
    - Пояснение: «Текущий прогресс будет сброшен, а результат не попадет в рейтинг.» / «Current progress will be reset and no score will be recorded.»
    - Действия: «Продолжить игру» (первичная, безопасная) и «Прервать» (вторичная/опасная кнопка сброса).
- **Сброс состояния при подтверждении:**
  - Вызов `api.abortSession(session.id)`.
  - Очистка `clearSessionId()`.
  - Сброс локального состояния: `setSession(null)`, `setDraft(zeroDraft())`, `setName("")`, `setError("")`.
  - Обновление публичного события через `refreshEvent()`.

## 3. Локализация (i18n)

Ключи в `client/src/i18n.ts`:

- `abortConfirmTitle`: RU — «Прервать текущую игру?», EN — «Quit current game?»
- `abortConfirmCopy`: RU — «Прогресс матча будет аннулирован, а данные не попадут в лидерборд. Вы вернётесь на стартовый экран.», EN — «Match progress will be cancelled and will not be added to the leaderboard. You will return to the start screen.»

- `abortConfirmAction`: RU — «Да, прервать», EN — «Yes, quit»

## 4. План тестирования (TDD)

1. **Серверные юнит/интеграционные тесты (`server/test/sessions.test.js`):**
   - Тест на удаление активной сессии через `DELETE /api/sessions/:id`:
     - Проверка удаления участника и портфеля.
     - Проверка возможности повторной регистрации с тем же именем после аборта.
     - Проверка, что после аборта эндпоинт `/api/event` показывает `leaderboard: []`.
     - Проверка ошибки `404` при повторном удалении или неверном `id`.
     - Проверка запрета удаления завершенной игры (`COMPLETED`).
2. **Типизация:** `npm run typecheck` во всех воркспейсах.
3. **Сквозной запуск:** `npm run test` (все тесты проходят).
4. **Проверка в браузере:** запуск локального dev-сервера и ручная проверка клика, модалки и возврата на стартовый экран.
