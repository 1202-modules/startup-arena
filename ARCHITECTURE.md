# Архитектура v2

Источники требований: DECISIONS.md, PRODUCT_SPEC.md, GAME_RULES.md. Один ноутбук, локальный REST, один активный участник. React + TypeScript + Vite; Node + TypeScript + Express; SQLite/better-sqlite3. WebSocket, аккаунты и AI отсутствуют.

## Слои

- `shared/src/index.ts`: константы, DTO RU/EN, типы шести компаний, точное распределение по весам, правила мест награждения.
- `server/src/scenarios/model.ts`: целочисленная экономика и дисконтированная оценка; `generated.ts`: шесть определений внешних шоков и предыстория; `catalog.ts`: версии v1/v2. Никаких импортов этих файлов в client.
- `projections.ts`: только текущие метрики, предыгровая/раскрытая история, результат запрошенного квартала. Данные definition и будущие исходы остаются на сервере.
- `db/migrations.ts`: атомарная миграция до user_version=3. `events/event-store.ts`: один текущий event, точный общий рейтинг, название/закрытие/новый event.
- `sessions/session-store.ts`: состояние игры, транзакции подтверждения, идемпотентность, восстановление, персональный разбор по собственным сохранённым портфелям.
- `app.ts`: REST, проверка пароля timing-safe, bearer авторизация кабинета на 15 минут в памяти процесса, CSV/SQLite выгрузки только после входа. API no-store.
- `client/src/App.tsx`: загрузка, восстановление, очередь автосохранения, переходы, закрытие и церемония; `game-ui.tsx`: бренды, графики, распределение/результаты/разбор; `organizer-ui.tsx`: кабинет; `i18n.ts`: RU/EN; `styles.css`: сетка и анимации.

## Сохранение и переходы

ROUND_1_DECISION → ROUND_1_RESULT → ROUND_2_DECISION → ROUND_2_RESULT → ROUND_3_DECISION → ROUND_3_RESULT → COMPLETED. Черновик сохраняется с задержкой 450 ms. Подтверждение отменяет ожидающий таймер, ждёт уже начатую очередь, сохраняет точный портфель и затем подтверждает. При перезагрузке сервер возвращает состояние; localStorage хранит только id сессии, язык и факт просмотра церемонии.

`confirmRound` выполняет запись портфеля, результата и капитала одной SQLite транзакцией; повтор не начисляет прибыль снова. `completeSession` завершает участника ровно один раз. Все записи после закрытия отвергаются. Один event использует один scenario_id/model_version и один набор результатов для всех участников.

## API

| Метод | Путь | Доступ и назначение |
| --- | --- | --- |
| GET | /api/health, /api/event | публичный статус/рейтинг, без скрытого сценария |
| POST | /api/sessions | имя 2–24 символа, RU/EN, 100000 cents |
| GET | /api/sessions/:id | восстановление собственной сессии |
| PUT | /api/sessions/:id/portfolio | точный черновик |
| POST | /api/sessions/:id/rounds/:round/confirm | раскрытие текущего квартала |
| POST | /api/sessions/:id/next, /complete | следующий этап/итог |
| POST | /api/event/finalize | пароль требуется каждый раз; активный игрок блокирует закрытие |
| POST | /api/organizer/login | пароль → краткоживущий token |
| GET | /api/organizer | bearer; состояние, активные/завершённые, версия |
| PATCH | /api/organizer/event | bearer; название 2–60 символов открытого event |
| POST | /api/organizer/event/new | bearer; только после закрытия; не теряет историю |
| GET | /api/organizer/ranking.csv | bearer; точные центы, экранирование формул |
| GET | /api/organizer/backup.sqlite | bearer; консистентный serialize snapshot |
| POST | /api/organizer/downloads | bearer; одноразовая ссылка на выбранный CSV/SQLite |
| GET | /api/downloads/:ticket | случайный ticket на один файл, 60 секунд максимум, одно использование |

В браузере используются обычные HTTP-загрузки: основной token и пароль не передаются в URL. Ticket истекает не позднее авторизации кабинета и удаляется перед выдачей файла. Неизвестный, повторный и истёкший ticket возвращает 401. Прямые bearer-выгрузки сохранены для API.

SQLite serialize включает актуальные WAL-страницы. В экспортируемом буфере байты формата 18/19 переводятся в rollback (0x01), чтобы снимок открывался самостоятельно; исходная БД остаётся WAL. Это рекомендованный способ для сериализации в [документации SQLite](https://www.sqlite.org/c3ref/deserialize.html). Проверяется файловый WAL-источник, открытие буфера и отдельного read-only файла, integrity_check и совпадение рейтинга.

## Запуск и ограничения

Express слушает только 127.0.0.1, production отдаёт Vite build с того же origin. В development используется Vite proxy. Внешние шрифты, картинки и сетевые сервисы не нужны. Графики — SVG с доступными текстовыми значениями; для локализации используются i18next/react-i18next, дополнительная chart зависимость не потребовалась. Это техническое уточнение рекомендуемого MVP, поведение локализации и истории сохранено.

Существующие event остаются на v1, новый event — v2. Пароль в `.env`, token только в React памяти, после перезапуска сервера вход повторяется. Это локальное доверенное устройство; публичное размещение и удалённые игроки не входят в требования.
